# ADR 0026 — Unified logical input (AAA-06)

Date: 2026-09-26
Status: Accepted
Supersedes: raw DOM input bindings in `player.js` / `main.js`

## Context

`Player` previously owned raw `keydown`/`keyup` DOM listeners (WASD/arrows,
E=enter/exit, Space=jump) plus a click-to-lock instructions overlay, and
`main.js` owned a `keydown` pause handler. Device-specific input was tangled
into gameplay systems, making remapping impossible and Node-side verification
fragile (the harness had to tolerate real DOM listeners).

AAA-06 asks for an `input/` action-map layer + keyboard/mouse/touch/gamepad
adapters, and for stripping raw DOM bindings out of `player.js`.

## Decision

Introduce a logical input layer under `src/input/`:

- `action_map.js` — `ActionMap` maps logical actions (`moveForward`,
  `moveBackward`, `moveLeft`, `moveRight`, `enterExit`, `jump`, `pause`,
  `lock`) to physical codes. Pure data, remappable per-action, DOM-free.
- `keyboard.js` / `mouse.js` / `touch.js` / `gamepad.js` — adapters that
  translate device events into logical actions through the ActionMap. All are
  Node-safe: with a stub DOM they bind nothing or bind a no-op and report
  `bound=false`.
- `index.js` — `InputManager` combines all adapters into one action state:
  held `actions` (move) consumed each frame, plus an edge-triggered one-shot
  `events` queue (`enterExit`/`jump`/`pause`/`lock`) drained once per press.

`Player` now takes an optional `InputManager` (defaults to one built over its
domElement), reads `input.actions.moveForward/...`, drains
`input.drain()` for enterExit/jump, and owns no raw `keydown`/`keyup`/`click`
DOM bindings. The click-to-play overlay + pointer-lock click live in
`MouseAdapter`; pause (`KeyP`) is a logical action wired in `main.js` to
`App.togglePause`; lock (`Enter`/click) is wired to `player.controls.lock`.

## Consequences

- Input intent is decoupled from physical device; remapping is a single
  `ActionMap.remap(action, codes)` call.
- `player.js` / `main.js` contain no raw input listeners; adapters own device
  details.
- The verification harness can construct `ActionMap`/`KeyboardAdapter`/
  `InputManager` deterministically without a browser (pure mapping + stub DOM).
- Held actions stay on the per-frame path; one-shot actions are
  edge-triggered (fire exactly once per physical press), preventing double
  enter/exit or jump events.
- Later work (AAA-07 settings/remap UI) can persist `ActionMap.snapshot()`
  bindings and rehydrate.
