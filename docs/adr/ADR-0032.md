# ADR 0032 — Wilderness renderer + planet-driven streaming (`src/terrain.js`)

Date: 2026-09-27
Status: Accepted
Related: ADR 0031 (planetary surface model), ADR 0006 (geometry merging),
ADR 0011 (instanced buildings), ADR 0012 (render-distance LOD), ADR 0016
(minimap), ADR 0012/0022 (road graph), ADR 0030 (streaming budget)

## Context

`ChunkManager.loadChunk()` decided what a chunk *was* with three hard-coded
predicates (`dist < 6`, `|cx| ≤ 5`, `|cz| ≤ 5`) and there was exactly one
non-city renderer: `createWastelandChunk`, which drew a brown plane and nothing
else. Once ADR 0031 made the planet answer "what is this place?", three things
had to change together or the world would have been *more* wrong than before:

* streaming still built origin-centric cities and grey void;
* `RoadGraph` carried its own private copy of the old rules, so cars could not
  route in any city the planet actually placed;
* the minimap still reported `city / highway / wasteland`, so the HUD would have
  said "Wasteland" while the player drove through a forest.

Rendering the wilds also exposed a latent engine bug: `mergeGeometries()` had
been *silently rejecting* whole foliage batches for as long as the game has
existed.

## Decision

1. **New layer: `src/terrain.js` renders everything that is not a city.**
   `world.js` keeps the city builders; `terrain.js` owns the wilds. Chunk
   classification comes from `planet.classifyChunk()` in exactly one call, so
   renderer, population systems, road graph and HUD cannot disagree.

2. **Ground is a shared-boundary height grid.** One 7×7 vertex grid per chunk,
   sampled through `planet.groundHeightCached()`, with per-vertex biome tint and
   `vertexColors`. Because boundary vertices sample identical world positions in
   both neighbours, the surface is seamless with **no stitching pass** — and the
   whole chunk is one geometry with 49 vertices, so terrain is essentially free.

3. **Water is per-cell, not per-chunk.** Only cells whose centre is below the
   waterline get quads, so lakes and rivers keep their outline instead of every
   wet chunk becoming a sea. Waterline materials are transparent with
   `depthWrite: false`, so opaque terrain renders first and water floats over it.
   Sea / lake / river get distinct materials (roughness + opacity + tint).

4. **Ecology is data, and it is instanced.** `PROP_TYPES` describes each scatter
   prop as a list of (geometry, material) parts plus size and clump hints;
   multi-part props (mushroom = stem + cap, cactus = body + arm, flower =
   stem + petal head) share one instance transform set, so a chunk of forest
   floor is a handful of `InstancedMesh` draws. Which species grow where comes
   from `BIOME_TABLE` (`trees`, `props`, `flora`), never from an inline constant.
   Cold biomes reuse the *same* tree archetypes with a snow foliage material
   rather than inventing a second forest.

5. **Determinism per chunk.** Every scatter decision is drawn from a per-chunk
   `RNG(chunk coords ⊕ planet seed)`, so the same place always grows the same
   forest across stream cycles — which is what lets the harness assert
   tree/prop/collider counts twice and demand equality.

6. **Wilderness LOD drops the ecology, keeps the ground.** Far chunks render the
   ground grid only (no trees, no props, no colliders). Foliage is the expensive
   part of a wild chunk and it is also the part you cannot resolve from a
   kilometre away.

7. **All consumers read the planet.** `ChunkManager.classify()` is the single
   entry point; `RoadGraph` accepts an injected `classify` (planet-backed, with
   the historic rules kept as the *default* so the golden topology snapshot does
   not move) and grows nodes lazily via `ensure()` because the road network is no
   longer inside a fixed radius; `Minimap` is planet-driven and now shows biome
   colour, city pins and a nearest-settlement line.

8. **Fix: foliage prototypes are non-indexed.** `IcosahedronGeometry` (leaves) has
   no index buffer while `CylinderGeometry` (trunks) and `ConeGeometry` (pines)
   do. Mixing them in one merge batch made `BufferGeometryUtils.mergeGeometries()`
   log a warning and return `null` — so entire tree species vanished from chunks,
   and in the city path the result was a `Mesh` built from a null geometry.
   All shared prototypes are now built with `.toNonIndexed()`, and both merge
   helpers bail out instead of constructing a mesh from `null`.

## Consequences

* The browser path was verified with real pixels for the first time: a mid-day
  forest chunk streams 112 trees + 676 props, wet chunks carry water meshes, and
  the frame has 116 distinct colour buckets (before this change it was one brown
  plane). Two capture gotchas are recorded in the roadmap notes: the
  click-to-play overlay (`rgba(0,0,0,0.8)`, z-index 1000) must be hidden or a
  screenshot is 80 % black, and capture needs `--headless=new` — old headless
  composites WebGL unreliably.
* Props are collidable (trunk-sized boxes for trees, sized boxes for rocks),
  driving through a forest now stops the player; undergrowth stays walkable.
* Rivers and roads still cross water without bridges, and city cores are graded
  flat, which is exactly the job of PLANET-04.
* `createWastelandChunk` is deleted: on a planet there is no such thing as an
  empty chunk.
