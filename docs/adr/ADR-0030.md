# ADR 0030 — Streaming budget + queue + chunk pooling; single per-frame stream update (AAA-10)

Date: 2026-09-26
Status: Accepted
Supersedes: unbounded per-frame streaming + double `chunkManager.update()` in main.js
Related: ADR 0029 (broadphase), ADR 0022 (LOD)

## Context

`chunk_manager.update()` streamed the whole 7x7 active set on the first call and
did one LOD rebuild per frame, while `main.js` called `update()` twice (once at
init, once per sim step). A single frame could stream the entire visible world,
and the init-time call duplicated the first per-frame stream.

## Decision

1. **Streaming budget + queue** — `ChunkManager` gains `streamBudget` (default 3)
   and `pendingLoads`. `update()` enqueues every missing active chunk, then
   drains at most `streamBudget` loads per call. LOD rebuilds count against the
   same budget instead of `return`-ing after one. Streaming work per frame is
   capped and spread across frames.
2. **Chunk pooling** — `chunkPool` (a Map keyed by chunk id) stores unloaded
   chunkData (mesh + colliders still attached). `loadChunk` first checks the
   pool; a re-stream of the same chunk id reuses the pooled object and skips the
   fresh geometry allocation, re-spawning population for full-detail city chunks.
3. **Single stream update** — the redundant init-time `chunkManager.update()` in
   `main.js` is removed. The first per-frame sim update enqueues + drains the
   initial chunks on budget, so the world streams in over a few frames.

## Consequences

- A frame no longer streams the whole visible world: streaming is spread across
  `streamBudget` chunks per update, keeping frame cost predictable.
- Chunks that leave and re-enter the render radius reuse their geometry instead
  of rebuilding — lower GC and mesh churn.
- The world appears progressively (a few chunks per frame) rather than all at
  once on the first frame; acceptable for the streaming-city model.
- `update()` remains the single streaming entry point, called once per sim step.
