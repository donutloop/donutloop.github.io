# ADR 0028 — Replay-safe save/load (`core/save.js`)

Date: 2026-09-26
Status: Accepted
Supersedes: ad-hoc state persistence scattered across modules
Related: ADR 0022 (seeded deterministic RNG), ADR 0023 (layered core modules)

## Context

AAA-08 needs a persisted save/load that is **replay-safe**: because the world
is seeded deterministically (ADR 0022), a saved record carrying the seed +
sim-clock position + player state + progress must be sufficient to reproduce
the same run. Any wall-clock or nondeterministic field in the record would
break that guarantee and make verification impossible.

## Decision

Introduce `src/core/save.js` exposing a `SaveGame` class:

- `capture({ seed, player, simClock, progress, meta })` builds a single plain
  JSON snapshot: `{ version, seed, player, simClock, progress, meta }`.
- `serialize()` / `fromJSON()` give a deterministic JSON round-trip.
- `save()` / `load()` persist through the same Node-safe storage shim as
  settings (`createStorage`).
- `fingerprint()` is an FNV-1a checksum over the serialized record; two
  captures of identical state MUST fingerprint identically — this is what
  verification asserts for replay-safety.
- `restore({ player, simClock })` resumes a snapshot back onto live state
  (player position, car state, sim-clock steps/accumulator). It works over
  THREE objects (browser) OR plain `{x,y,z}` objects (Node harness).
- The record carries **no wall-clock timestamp** — only derived sim time
  (`steps * fixedDt`), which is deterministic from the clock.

`player` and `simClock` may be live instances or plain snapshots, so the whole
system is testable in Node with no browser/WebGL context.

## Consequences

- A saved game is a small, deterministic JSON record: seed + player + clock +
  progress. Restoring it reproduces the deterministic world and resumes state.
- The browser path exposes `window.saveGame` / `window.__worldloop.saveGame`
  and captures an autosave at init (seed + player + sim clock + score/events).
- Verification covers capture, serialize/fromJSON, save/load, deterministic
  fingerprint, and restore/resume (check_world.mjs + `save_sim.mjs` suite).
- A later AAA-21 save/continue UI can layer slot labels on top of `meta`
  without changing the record schema (versioned via `SAVE_VERSION`).
