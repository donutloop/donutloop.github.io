# ADR 0023 — Layered architecture: App state machine, input abstraction, settings/save

Date: 2026-09-26

## Status

Accepted

## Context

`src/main.js` is a monolithic imperative `init()` with no game states
(boot/loading/menu/playing/paused/gameover), no pause, no persistence, and no
settings. `src/player.js` binds raw DOM `keydown`/`keyup` directly — no action
mapping, no remap, no touch/gamepad, no UI-vs-gameplay input separation.
`README.md` still tells players `1/2/3` changes weather although ADR 0004
removed manual weather — input and docs drift.

## Decision

Refactor into a layered architecture:

```text
entry (index.html) → boot (main.js) → App (state machine)
  ├─ core/   config, events, time, rng, settings, save
  ├─ world/  chunk mgr, world.js, road graph
  ├─ systems/ traffic, lights, parking, peds, planes, EMS, construction,
  │           weather, effects, minimap
  ├─ render/ scene, camera, renderer (capability tiers), postfx, assets, audio
  ├─ ui/     HUD, menu, pause, settings, loading, dialog, a11y
  └─ input/  action-map + keyboard/mouse/touch/gamepad adapters
```

`player.js` consumes actions from `input/` instead of DOM events. Settings
(quality tiers, control remap, audio) persist via `core/settings.js`
(localStorage); save/load via `core/save.js` (world seed + player state).

## Consequences

- Gameplay states become testable and pause/save/resume become first-class.
- Input remap, touch, and gamepad become adapter additions, not rewrites.
- Larger refactor surface; land in small commits (AAA-05..08) keeping
  `check_world.mjs` green and the render clean.
- Docs (README) updated to match actual controls.
