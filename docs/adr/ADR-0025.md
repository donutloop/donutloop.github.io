# ADR 0025 — Frame loop hygiene: one update per frame, clamped dt, frame budget (AAA-02)

Date: 2026-09-26

## Status

Accepted

## Context

The animation loop in `src/main.js` had three latent problems:

1. **Double update** — the per-frame callback called `chunkManager.update()`
   twice, so chunk streaming ran at 2× the intended rate and could double-load
   work on a single frame.
2. **Unclamped `dt`** — `delta` was computed inline from `performance.now()`
   and passed to every system unclamped. A backgrounded tab or a long stall
   produced a giant delta, letting physics/weather/traffic "jump" across many
   seconds in one frame.
3. **No frame budget** — if a frame's update+render cost exceeded the frame
   time, the sim simply kept running, accumulating lag (a "spiral of death").

## Decision (AAA-02)

Introduce a shared `FrameLoop` (`src/loop.js`) that owns the loop clock:

- **Exactly one update per frame** — the `animate(loop, update)` driver in
  `src/scene.js` calls `update(dt)` once per non-skipped frame; the duplicate
  `chunkManager.update()` is removed.
- **Explicit clamped `dt`** — `FrameLoop.tick(now)` computes `dt` from the
  previous timestamp and clamps it to `maxDt = 0.1s`, so a backgrounded-tab
  stall can never jump the sim. The clamped `dt` is the only delta fed to every
  system.
- **Frame budget** — after each frame `reportWork(ms)` records the measured
  update+render cost. If it exceeds `budgetMs = 16.7ms` (≈60fps), the NEXT
  frame's update/render work is dropped (a budget-skip), so the sim drops a
  frame instead of spiraling.

The loop state (clamped dt, skipped frames, over-budget frames) is recorded
into `FrameBudgetTelemetry.recordBudget()` each frame so the behavior is
machine-visible and verifiable.

## Consequences

- The sim is deterministic under stalls: `dt` is always clamped to `maxDt`.
- The sim recovers instead of spiraling: over-budget frames drop the next frame.
- Exactly one update runs per frame, so chunk streaming and all systems tick
  at the intended rate.
- A follow-up (AAA-04) can layer a fixed-timestep accumulator on top of this
  clamped `dt` without changing system signatures.
- Trade-off: a budget-skip keeps the last rendered frame for one frame, which
  is a deliberate cost of dropping work under load.
